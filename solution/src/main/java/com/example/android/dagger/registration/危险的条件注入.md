
### **解释：条件字段注入（Conditional Field Injection）的问题**
在 `MainActivity.kt` 进行 **条件字段注入（Conditional Field Injection）**，即 **仅在用户已登录时才注入依赖**，是非常危险的。

#### **为什么危险？**
- **可能导致 `NullPointerException`（NPE）**
  由于 Dagger 只会注入依赖 **当特定条件满足时**，如果代码在注入前尝试访问这些字段，就会导致 **NPE**。
- **开发人员需要手动管理条件，容易出错**
  需要开发人员明确 **在哪些情况下注入，在哪些情况下不注入**，这增加了代码复杂度，容易遗漏边界情况。

---

### **✅ 解决方案：使用 SplashScreen 进行路由**
为了避免条件字段注入的风险，可以在应用启动时 **先检查用户状态**，然后决定导航到哪个界面：
- **未登录** → 导航到 `LoginActivity`
- **未注册** → 导航到 `RegistrationActivity`
- **已登录** → 直接进入 `MainActivity`

这样，**`MainActivity` 只会在确保依赖可用的情况下被访问**，避免了 `NullPointerException`。

---

### **案例示例**
#### **❌ 错误示例（条件字段注入，可能导致 NullPointerException）**
```kotlin
class MainActivity : AppCompatActivity() {

    @Inject
    lateinit var userManager: UserManager  // 仅在用户已登录时注入

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        if (userIsLoggedIn()) {
            (application as MyApp).appComponent.inject(this)  // 仅在登录时注入
        }

        // ⚠️ 如果 userManager 未被注入，这里会导致 NullPointerException
        userManager.getUserData()
    }

    private fun userIsLoggedIn(): Boolean {
        return userManager.isLoggedIn()  // ⚠️ 这里可能会崩溃，因为 userManager 可能为 null
    }
}
```
❌ **问题：**
- `userManager` 仅在 `userIsLoggedIn()` 返回 `true` 时注入，但在 `userIsLoggedIn()` 方法内部却依赖了 `userManager`，**可能导致 `NullPointerException`**。
- `MainActivity` **不应该关心用户是否登录**，它应该 **只在用户已登录时被访问**。

---

#### **✅ 正确示例（使用 `SplashScreen` 进行路由）**
```kotlin
class SplashScreenActivity : AppCompatActivity() {

    @Inject
    lateinit var userManager: UserManager  // 这里安全注入

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        (application as MyApp).appComponent.inject(this)  // 这里总是注入，不会条件注入

        when {
            !userManager.isRegistered() -> navigateTo(RegistrationActivity::class.java)
            !userManager.isLoggedIn() -> navigateTo(LoginActivity::class.java)
            else -> navigateTo(MainActivity::class.java)
        }
    }

    private fun navigateTo(activityClass: Class<*>) {
        startActivity(Intent(this, activityClass))
        finish()  // 关闭 SplashScreen
    }
}
```
✅ **改进点：**
- `SplashScreenActivity` 先检查用户状态，然后**只导航到合适的界面**，确保 `MainActivity` 只在依赖可用时被访问。
- `MainActivity` **不需要手动管理依赖注入的条件**，所有逻辑都被抽离到了 `SplashScreenActivity`，使代码更清晰。

---

### **总结**
| **方法** | **优缺点** |
|----------|------------|
| **条件字段注入（Bad Practice）** | ⚠️ 可能导致 `NullPointerException`，增加代码复杂度，容易遗漏边界情况。 |
| **使用 `SplashScreen` 进行路由（Best Practice）** | ✅ 让 `MainActivity` 只在依赖可用时访问，避免 `NPE`，代码清晰。 |

✅ **结论**：避免在 `MainActivity` 进行条件字段注入，而是使用 `SplashScreen` 统一管理用户状态，并决定正确的导航路径。
