
### **Dagger2 作用域（Scoping Rules）解释**

在 Dagger2 中，作用域（Scope）用于管理依赖项的生命周期。作用域的主要规则如下：

1. **当某个类型（类）被标记为某个作用域（Scope）时，它只能被同样标记为该作用域的 `Component` 使用。**
   - 例如，如果一个 `Repository` 类被 `@Singleton` 标记，则它只能由同样标记了 `@Singleton` 的 `Component` 提供。

2. **当一个 `Component` 被标记为某个作用域时，它只能提供具有相同作用域的类型，或没有作用域的类型。**
   - 这意味着 `@Singleton` 作用域的 `Component` 无法提供 `@ActivityScope` 标记的类型，因为作用域不同。

3. **子组件（Subcomponent）不能使用其父 `Component` 已经使用过的作用域。**
   - 例如，父 `Component` 使用了 `@Singleton`，那么它的子 `Component` 不能再次使用 `@Singleton`，但可以使用 `@ActivityScope` 或其他自定义作用域。

4. **`Component` 和 `Subcomponent` 共同遵循作用域规则。**
   - `Subcomponent` 继承了 `Component` 的依赖项，但作用域必须是不同的（即不能重复使用 `@Singleton` 作用域）。

---

### **案例分析**
#### **1. 正确的作用域使用**
```kotlin
import dagger.Component
import javax.inject.Inject
import javax.inject.Singleton

// 一个被 @Singleton 作用域标记的 Repository
@Singleton
class Repository @Inject constructor()

// 被 @Singleton 作用域标记的 ApplicationComponent
@Singleton
@Component
interface ApplicationComponent {
    fun getRepository(): Repository
}
```
✅ **解释：**
- `Repository` 被 `@Singleton` 标记，表示它的生命周期是整个应用程序级别的单例。
- `ApplicationComponent` 也被 `@Singleton` 标记，所以它可以提供 `Repository` 实例。

---

#### **2. 组件作用域匹配**
```kotlin
import dagger.Component
import javax.inject.Inject
import javax.inject.Singleton

@Singleton
class Repository @Inject constructor()

@Singleton
@Component
interface ApplicationComponent {
    fun getRepository(): Repository  // ✅ 作用域匹配，可以提供
}

@Component
interface ActivityComponent {
    fun getRepository(): Repository  // ❌ 报错！作用域不匹配
}
```
❌ **错误点：**
- `Repository` 被 `@Singleton` 标记，而 `ActivityComponent` 没有 `@Singleton`，所以它无法提供 `Repository` 实例。

---

#### **3. 父组件与子组件的作用域**
```kotlin
import dagger.Subcomponent
import javax.inject.Inject
import javax.inject.Singleton

// Application 级别的单例依赖项
@Singleton
class Repository @Inject constructor()

@Singleton
@Component
interface ApplicationComponent {
    fun getRepository(): Repository
    fun activityComponent(): ActivityComponent  // 生成子组件
}

// Activity 级别的依赖项
@ActivityScope
class ActivityHelper @Inject constructor()

@ActivityScope
@Subcomponent
interface ActivityComponent {
    fun getActivityHelper(): ActivityHelper
}
```
✅ **正确用法：**
- `ApplicationComponent` 作用域是 `@Singleton`，可以提供 `Repository`。
- `ActivityComponent` 作用域是 `@ActivityScope`，不能与 `ApplicationComponent` 复用 `@Singleton`，但可以提供 `@ActivityScope` 作用域的 `ActivityHelper`。

---

### **错误示例：子组件不能复用父组件的作用域**
```kotlin
@Singleton
@Subcomponent
interface ActivityComponent {  // ❌ 报错，不能复用 @Singleton
    fun getActivityHelper(): ActivityHelper
}
```
❌ **错误点：**
- `@Subcomponent` 不能使用父 `Component` 已经使用的 `@Singleton`，否则会违反作用域规则。

---

### **总结**
1. **作用域（Scope）定义了依赖项的生命周期，必须在 `Component` 和提供的类型之间匹配。**
2. **`Component` 只能提供与自己相同作用域或无作用域的类型。**
3. **`Subcomponent` 不能重复使用父 `Component` 的作用域，但可以定义自己的作用域。**
4. **合理划分作用域可以有效地管理对象的生命周期，减少不必要的创建和销毁，提高性能。**
